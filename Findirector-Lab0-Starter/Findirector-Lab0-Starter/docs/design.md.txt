# Проектирование системы (ЛР2)

## 1. Архитектура приложения (ЛР2-A1, ЛР2-A2)
Система разделена на 4 слоя:
1. **Domain (Финансовая модель):** Содержит бизнес-логику, формулы и сущности (`Plan`, `MonthPlan`, `MonthReport`). Не зависит ни от чего.
2. **Application (Прикладные операции):** Содержит сценарии использования (прогноз, сравнение, сохранение). Зависит от Domain. Определяет интерфейс `IPlanRepository` для хранения.
3. **Infrastructure (Хранение):** Реализует `IPlanRepository` (например, сохранение в JSON или БД). Зависит от Application.
4. **UI (Интерфейс):** Консоль или веб-сайт. Вызывает операции из Application.

## 2. Контракты операций (ЛР2-Д3)

### 2.1. Прогноз (Calculate)
* **Вход:** План (3 месяца параметров), Стартовые деньги (decimal), Стартовая дебиторка (decimal).
* **Результат:** Список из 3 отчётов (`MonthReport`). Важно: остаток денег и дебиторка с конца 1-го месяца переносятся в начало 2-го.
* **Ошибки:** Отрицательные параметры, процент оплаты > 100.

### 2.2. Сравнение (Compare)
* **Вход:** Два сохраненных плана (ID1, ID2).
* **Результат:** Таблица разницы показателей (Прибыль, Деньги) между планами.
* **Ошибки:** План не найден.

### 2.3. Сохранение (Save)
* **Вход:** Объект Плана.
* **Результат:** Уникальный ID сохраненного плана.
* **Ошибки:** Нет прав на запись, ошибка хранилища.

### 2.4. Список (List)
* **Вход:** Нет.
* **Результат:** Список кратких имен и ID всех сохраненных планов.
* **Ошибки:** Ошибка чтения хранилища.

### 2.5. Открытие (Open)
* **Вход:** ID плана.
* **Результат:** Загруженный объект Плана (все 3 месяца).
* **Ошибки:** Файл/запись не найдена, данные повреждены.

## 3. Обоснование решений (ЛР2-Д4)
* **Отделение расчёта от UI (SRP):** Принцип единственной ответственности. UI должен только показывать данные и ловить клики. Если мы завтра захотим сделать веб-версию вместо консоли, переписывать логику расчета не придется.
* **Хранилище через интерфейс (DIP):** Принцип инверсии зависимостей. Слой Application не должен знать, как именно сохраняются файлы (в JSON, SQLite или Excel). Он просто дергает метод `Save()` у интерфейса `IPlanRepository`. Это позволяет легко менять базу данных без переписывания бизнес-логики.
